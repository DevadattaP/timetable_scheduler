About This System

Automated academic scheduling using Integer Linear Programming

🎓 Objective

This system automates the creation of a feasible and optimized class timetable for any academic programme. It supports two planning modes: sections-based scheduling for fixed section timetables, and areas-based scheduling for parallel course delivery inside each area, while respecting faculty constraints and calendar availability.

⚙ How It Works
  • Choose either Sections mode or Areas mode, then configure the matching buckets, courses, faculty, mappings, and constraints in the Configure tab.
  • You can import configuration from an Excel file. Template
  • Click Generate Timetable to send the configuration to the LP solver.
  • The solver always tries to satisfy all enabled Hard Constraints.
  • If the Consecutive Sessions Rule is enabled, the solver minimizes consecutive-period violations using a Soft Penalty Objective.
  • The generated timetable can be verified against all configured constraints.
  • You can export both configuration and timetable to Excel for backup or offline editing.
  • The timetable can be viewed and exported in various formats: section/area wise, course wise, or faculty wise.
🧭 Modes
  • Sections mode: Each section gets its own timetable and every available section slot is filled by exactly one class.
  • Areas mode: Each area can host multiple sessions in the same slot when the constraints allow it, so parallel delivery is possible inside that area.
  • Mappings: Sections mode uses section-course-faculty mappings, while Areas mode maps course to faculty only.
🔒 Hard Constraints
  • Session fulfillment: Every available slot must be filled by at max one class. Some slots may remain unused, if requirements are fulfilled already.
  • No Faculty Cloning: A faculty member cannot teach two sections simultaneously.
  • Max Daily Load: Faculty can teach at most N sessions per calendar day.
  • Course Spacing: A section cannot have the same course twice in one day.
  • Unavailability (optional): Faculty are not scheduled on blocked timeslots.
  • Course conflicts (optional): Courses in specified groups cannot be scheduled at the same time.
✨ Soft Constraint — Consecutive Sessions Rule
  • Configurable Consecutive Limit: Restrict how many consecutive periods the same course may appear (for a section if sections mode is enabled).
  • Flexible Period Unit: Consecutive tracking can be applied across weeks or days.
  • Reset Boundary: Consecutive counting may optionally reset at boundaries such as month, or remain continuous throughout the schedule.
  • Penalty-Based Optimization: Violations are treated as soft penalties in the LP objective function, while all hard constraints remain strictly enforced.
  • Violation Definition: A penalty is added whenever the same course appears in (max consecutive + 1) consecutive eligible periods (for the same section if sections mode is enabled).
  • Example 1: If Max Consecutive = 2 Weeks with Month Boundary, a penalty is triggered when the same course runs for 3+ consecutive weeks within the same month.
  • Example 2: If Max Consecutive = 1 Week with No Boundary, it works like an alternate week rule, and a penalty is triggered when the same course runs for 2+ consecutive weeks within the complete schedule.
✨ Soft Constraint — Session Spreading Rule
  • Even Distribution: Encourages sessions for each course (and section, in sections mode) to be spread uniformly across the full scheduling period rather than clustering at the start, end, or around other constraints.
  • Epoch-Based Tracking: The scheduling period is automatically divided into equal-length epochs — one epoch per required session. Each epoch represents the ideal window in which one session should fall.
  • Penalty-Based Optimization: An empty epoch (one that receives no session) contributes one penalty point to the LP objective. The solver minimizes total penalty while keeping all hard constraints strictly enforced.
  • Penalty Weight: The weight controls how aggressively spreading is prioritized relative to other soft constraints such as the consecutive rule. A higher weight pushes the solver to fill gaps more forcefully. Recommended range: 0.01 – 0.5.
  • Violation Definition: A penalty is added for each epoch that ends up with zero sessions. Over-filled epochs (more than one session) do not add a penalty — only empty epochs are penalized.
  • Example 1: A course requiring 4 sessions over a 16-week term creates 4 epochs of 4 weeks each. If sessions land in weeks 1, 2, 3, and 14 — epochs 0, 0, 0, and 3 — then epochs 1 and 2 are empty, giving a penalty of 2.
  • Example 2: Same course, sessions in weeks 2, 6, 11, and 15 — one per epoch — gives a penalty of 0. This is the ideal outcome the solver aims for.
